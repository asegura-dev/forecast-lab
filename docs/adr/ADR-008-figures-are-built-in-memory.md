# ADR-008 - Figures are built in memory and committed as PNG

- **Status:** Accepted - **built** (`research/plots.py`, `train --figures`, 11 tests, and eight committed charts).
- **Date:** 2026-08-24
- **Follows:** [ADR-001](ADR-001-hexagonal-architecture.md), whose rule that `research` never touches disk decides where a figure may be saved, and [ADR-007](ADR-007-fitting-models-without-leaking.md), which produced the numbers being drawn.
- **Context:** Seven commits in, this repository was text. Tables in a terminal and tables in markdown, and nothing a reader could see. The original project drew nineteen charts across its two notebooks - and none of them could have revealed its mistake, because every one plots a model against itself. That is the interesting half of this decision: the problem was never that it lacked charts.

## Decision

### 1. `research/plots.py` returns `Figure` objects and never writes one

The layering guard now treats `savefig` as I/O, alongside `open` and `read_csv`.

*Why:* the rule that `research` cannot reach for data is what makes every function in it callable from a test with synthetic input and no filesystem. A plotting module is where that rule quietly erodes, because saving feels like part of drawing. It is not: deciding *where* output goes is the composition root's job, and `savefig` was a name the original I/O list did not anticipate. Adding it cost one line and closed a real hole.

### 2. Four figure types, chosen for what the original could not show

- **`edge_chart`** - every configuration against the constant predictor and the break-even line. **The chart the original needed and did not have.** Its two headline numbers, 51.53% and 51.86%, appear two rows apart in its own output; here they are a bar and a line, and the bar is under the line. On this data thirteen of eighteen bars fall below the baseline and exactly one clears break-even.
- **`roc_chart`** - the original drew this, but from hard labels, which collapses every curve into one kink and gave its Naive Bayes an AUC of exactly 0.5000. From probabilities the curves are real, and the finding is how completely they overlay the diagonal.
- **`confusion_grid`**, row-normalised - also in the original, kept because it renders something no table did. **In almost every panel the DOWN row and the UP row are the same**: the model predicts UP at the same rate whether price rose or fell. Measured across the eighteen configurations, the median gap between recall and (1 - specificity) is **0.0101**. That gap is Youden's J, so a median of 0.01 corresponds to an AUC of about 0.505. Normalising by row is what makes it visible; raw counts hide it behind the class imbalance.
- **`calibration_chart`** - not in the original at all. A model can rank acceptably and still be systematically overconfident, and at these effect sizes that is the difference between a probability worth acting on and a decorative one.

**Trade-off:** eighteen configurations is more than any of these charts comfortably holds. The ROC and calibration legends had to move outside the axes - an inline legend covered the diagonal, which on that chart is the entire argument - and `edge_chart` had to become horizontal bars, because eighteen labels like "HistGradientBoosting pca-90" smear into an unreadable band on a vertical axis. Both were found by looking at the output rather than by reasoning about it.

### 3. The PNGs are committed

`docs/status/figures/`, versioned, while `data/` stays ignored.

*Why:* they are derived statistics rather than vendor data, so redistributing them raises none of the questions the raw bars do - the same reasoning that lets the manifest be committed while the series is not. And the practical half matters more than it sounds: a research log whose charts exist only on the author's machine is not a research log. A reader on GitHub sees the argument or does not.

They are small - eight files, well under a megabyte - and regenerated by one command, so they cannot drift from the numbers without the command being re-run.

### 4. matplotlib, with the `Agg` backend, quarantined to one module

*Why matplotlib rather than plotly:* a PNG renders in a GitHub README and in a markdown log. An interactive HTML chart does neither. Plotly arrives with the dashboard, where interactivity has somewhere to happen.

*Why `Agg`, set before pyplot is imported:* the default backend probes for a display, which on a headless machine warns or blocks. A figure destined for a file never needs a window.

*Why quarantined:* matplotlib ships no type information, the same argument as `ta` and the estimator stack, and a test enforces it. It also keeps the backend dance in exactly one place, so no unrelated import can accidentally probe for a display.

## Consequences

**`sklearn` had to leave the plotting module, and that was the guard working.** The first version of `roc_chart` imported `roc_curve` directly, and the estimator quarantine caught it immediately. The fix was not to widen the exception but to move the computation: `metrics.roc_points()` returns coordinates, and the chart draws them. A figure is a drawing of numbers, and computing the numbers belongs with the other metrics - the guard pointed at a design problem rather than at an inconvenience.

**The command grows a `--figures` flag rather than a separate command.** The figures are a rendering of a run, not an independent artefact, and a `plot` command would have to refit every model to draw anything - or read a JSON payload, which is a second code path to the same picture.

**What is not drawn yet.** `correlation_comparison` exists and is tested but has no caller: it needs the EDA work, where the original's +0.923 gold-versus-S&P correlation gets recomputed on returns and shown to be an artefact of two trending series. That is the dashboard's Phase 4 material, and the function is here because it belongs beside the other figures rather than in a notebook.
