# Changelog

Notable changes to **forecast-lab**, newest first. This is a research lab rather than a released product, so entries are **dated** instead of versioned. It complements - it does not replace - the [STATUS logs](docs/status/) (what an experiment measured), the [ADRs](docs/adr/) (decisions and their reasoning), and the git history. Only notable changes are listed here; `git log` has every commit. The format loosely follows [Keep a Changelog](https://keepachangelog.com).

## 2026-08-27 - An audit of the repository against itself

A three-way audit compared every markdown file against the code, the JSON sidecars and the git tree. It found things a passing test suite cannot: claims about the repository's own behaviour that were false, figures that had drifted, and two decisions documented as done that had never been executed. What follows is what the audit found and what closing it changed.

### Added

- **The canonical dataset exists.** `fetch` had only ever run as a 240-bar smoke test, so **every published number was computed on the reference exports** - the dataset [ADR-002](docs/adr/ADR-002-data-source-and-symbol-set.md) sec. 1 says must never feed the engine. The decision was written, agreed, and never executed; nothing could notice, because both directories read identically and every command was pointed at the one holding data. There are now **11 symbols and 606,250 hourly bars from 2018-01**, verified against a 45-entry manifest. Gold goes from 23,181 bars to 51,147.
- **The gap finding replicates across venues.** Running the pipeline on both datasets: the fraction of bars whose horizon spans a gap is **4.37% at both**, to two decimal places, across two providers and twice the sample - a property of gold's calendar rather than of a feed. And price rises through those gaps 59.35% of the time in one and 56.40% in the other, far above the 50.8% of an ordinary hour. Measured once it was an observation; measured twice on independent data it is a finding.
- **And it moves the project's central argument.** The reference split leaves 3,478 test bars and a minimum detectable effect of 2.11 points, which cannot resolve the 1.92-point break-even it exists to test. The canonical split leaves **7,334 bars and an MDE of 1.45 points**, which can. "This design needs walk-forward" becomes "it needed walk-forward *or* more data", with both routes now measured.
- **Realised volatility, which had been described in the present tense since 2026-08-18 and did not exist.** Dropping VIX cost 55% of the sample on the promise of a substitute nobody wrote. It is now `realised_vol_24` and `realised_vol_168`, at the windows [ADR-002](docs/adr/ADR-002-data-source-and-symbol-set.md) sec. 4's own probe measured (+0.645 at 24h, flat past a week at +0.754).
- **The provenance manifest is committed**, which [ADR-002](docs/adr/ADR-002-data-source-and-symbol-set.md), the RUNBOOK, `docs/INDEX.md` and three STATUS logs had all asserted for a week. It never was, so `verify` - the command the reproducibility claim rests on - failed on a clean clone, and five markdown links pointed at nothing.
- **[STATUS 2026-08-24](docs/status/STATUS-2026-08-models.md) sec. 5, on selection instability.** Adding those two volatility columns **changed which model wins**, from LightGBM to XGBoost, while leaving every conclusion intact. That is worth more than the coincidence it cost: the previous version observed that the corrected pipeline selected the same model the original did and read it as corroboration. It was two draws from the same noise landing on the same number, and two columns were enough to separate them. Every feature added from here counts as a trial in the multiplicity accounting, measured before and after.

### Fixed

- **"Exactly one configuration clears break-even" was wrong - there were two**, and the repository's own table printed the second one ten lines above the sentence denying it. That is precisely the failure this project exists to document, committed by the project. (With realised volatility added it is one again, which is why the figure now comes from the sidecar rather than from prose.)
- **"A single split resolves about 0.85 points at 80% power" was a conceptual error**, repeated in four documents. 0.85 is **one standard error**; the minimum detectable effect is 2.49 of them - **2.17 points**. The mistake made the design look sharper than it is, and it contradicted the README's own MDE table. [ADR-004](docs/adr/ADR-004-labels-splits-and-baselines.md) had concluded that the design "can just about see" the 1.92-point break-even; it cannot see it at all, which strengthens the argument it was making. The `train` command now computes the MDE from the block it actually scored instead of quoting a number.
- **"The CLI is the only place that touches the filesystem" was false** - `ingest` reads and writes, which is its job. Stated in [ADR-001](docs/adr/ADR-001-hexagonal-architecture.md), in the conventions as a hard rule, and in `cli.py`'s own docstring. The real rule, and the one the layering guard enforces, is that **`research` never reaches for data**; the CLI is the only layer that *decides* what to read and where to write.
- **"Every command that produces a result offers `--json`" was false** - three of eight do. `align` does not, and it renders "the correction at the centre of the re-analysis", so the dashboard could not show it without scraping a Rich table.
- **The Quickstart did not work.** `fetch` writes to `data/raw` while `baseline`, `features` and `train` read `data/reference` by default, so the last three commands failed on any clean clone that followed the README in order.
- **[ADR-005](docs/adr/ADR-005-the-dashboard-runs-the-cli.md) claimed the JSON payloads were "pinned by the CLI's own tests".** No test exercises `interfaces/cli.py` at all. The ADR now records that as a debt it created rather than a guarantee it offers.
- **[ADR-002](docs/adr/ADR-002-data-source-and-symbol-set.md) contradicted itself in a single line** - "Status: Accepted - built" followed by "Nothing built yet" - and again forty lines on, where "Implementation status: Nothing built" preceded a list of what had been built.
- Assorted drift: `23,180` against `23,181` inside one ADR (the column counts **labels**, and the last bar has no successor); the ADX 99th percentile published as `6.908e-10` against a real `6.988e-10`; ADF sample size given as 23,000 when the code reads 5,000; three cross-references pointing one section short; test counts of 32 and 16 that were 31 and 17; three incompatible figures for the same `n_jobs` measurement; the eight figures called "well under a megabyte" at 1.4 MB; `tests/fixtures/` described in the gitignore and never created; and the break-even of 51.92% attributed to a measured 1.6 bps spread when it comes from an assumed 1 bp - 1.6 bps would put it near 53%.

## 2026-08-24 - Models, and the 2.06 points that hang on where you look

### Added

- **[ADR-007](docs/adr/ADR-007-fitting-models-without-leaking.md) and `research/models/`** - six estimators, three representations (raw, PCA at 95% and 90%), every transform fitted on the training block alone through an `sklearn.Pipeline` that cannot be fitted twice by accident. **Selection happens on validation; test is scored once, afterwards.** The original ranked by `Test_Accuracy` in one notebook and selected with `results_df['Test_AUC'].idxmax()` in the other, which turns the test set into a hyperparameter.
- **`forecast-lab train`**, with `--json`. Every row prints `edge` - accuracy minus the baseline - immediately after accuracy, and the table carries a literal `always-UP (from train)` row. The original had both numbers in its own output, two rows apart, and nowhere that their difference was computed.
- **[STATUS 2026-08-24](docs/status/STATUS-2026-08-models.md)** - the result. The honest pipeline selects **LightGBM**, the same model the original selected, and on test it loses to a constant predictor by **0.64 points**; the original reported the same model losing by 0.33. Two pipelines, different data handling, same choice, same sign.
- **[ADR-008](docs/adr/ADR-008-figures-are-built-in-memory.md), `research/plots.py` and `train --figures`** - the repository stops being text. `research` builds `Figure` objects and never writes one; the layering guard now treats `savefig` as I/O, which was a hole the original list did not anticipate. Eight PNGs are committed under `docs/status/figures/`, because a research log whose charts exist only on the author's machine is not a research log.
- **The chart the original needed and did not have**: every configuration against the constant predictor and the break-even line. Thirteen of eighteen fall below the baseline; two clear break-even, and they are the top two of eighteen draws that section 3 of the STATUS shows are indistinguishable from coin flips. Its two headline numbers appear two rows apart in its own output - here they are a bar and a line, and the bar is under the line.
- **A finding the tables could not show.** Row-normalised confusion matrices make it plain that in almost every model the DOWN row and the UP row are identical: the prediction is independent of the answer. Across the eighteen configurations the median gap between recall and (1 - specificity) is **0.0101** - that gap is Youden's J, so 0.01 corresponds to an AUC of about 0.505.
- **Availability is discovered by building each estimator**, and every model that could not be run is printed with its reason. A comparison that quietly omits two models is a comparison of a different experiment than the table claims to describe.

### Fixed

- **LightGBM and XGBoost would not load on a clean Windows 11 install**, and the fix was a version pin rather than code. Both load a native DLL through `ctypes`, and an application control policy refuses any binary without an established reputation - so 4.7.0 and 3.4.1 are blocked across repeated attempts while **4.6.0 and 3.0.5 load first try**. Without that diagnosis this work would have compared four models and silently dropped the one the original selected. Recorded in `pyproject.toml`, because `uv lock --upgrade` would walk straight past a range pin.
- **[ADR-006](docs/adr/ADR-006-features-and-stationarity.md) claimed too much about PCA.** It offered price levels as the plainest explanation for the original collapsing 63 features into 6 components. Measured with every level already removed: PCA at 90% still retains **6 components from 17 features**. Indicators computed from one price series are intrinsically redundant; the levels made it worse rather than causing it.
- **`train` was not byte-reproducible**, and three consecutive runs proved it with three different hashes. `RandomForestClassifier(n_jobs=-1)` - the original's setting - sums 100 tree votes in whatever order the workers finish, and floating-point addition is not associative, so probabilities moved by up to **3.3e-16**. No conclusion changed, which is precisely why it would have survived: a discrepancy that changes nothing is one nobody investigates. `n_jobs` is not a hyperparameter (`random_state` fixes every tree), so the forest is identical and only the summation order differs. Takes the command from about six seconds to twelve. A test pins it with `array_equal` rather than `allclose`, and all six estimators were then verified deterministic.
- **A LightGBM warning corrupted `--json` output.** It records column names at fit time and hands sklearn a bare array back at predict time, so sklearn warns once per block per model. Suppressed narrowly - by category and message - with an assertion that the columns really are identical, which is the guarantee the warning was gesturing at.

## 2026-08-24 - Features that cannot carry a price, and a guard corrected twice by real data

### Added

- **[ADR-006](docs/adr/ADR-006-features-and-stationarity.md) and `research/features/`** - the feature matrix, built in the order that does not fabricate data. Indicators are computed on **each symbol's native grid, before any reindexing**: the other order manufactures exact-zero returns on every row where an auxiliary is stale, and since a symbol is stale precisely when its venue is shut, that artefact tracks the hour of the day. A tree fed those columns learns a session clock and a report calls it a macro signal. VIX is carried on 8.0% of rows and DXY on 7.1%, so it is not a small effect.
- **A stationarity gate that is checked by measurement rather than by a list of names.** Every column is rebuilt on prices multiplied by ten; one that moves is a price level. Gold runs 1,616 to 4,378 across this sample, so a column carrying that level puts the test block outside the training data's support - which is the plainest explanation for the original PCA collapsing 63 features into 6 components. All seventeen columns pass. ADF and KPSS run beside it and are **reported, never decisive**: at this sample size the ADF rejects a unit root on almost every column, and both tests are invalid under the regime change that characterises this data.
- **`forecast-lab features`**, with `--json` and both modes. WHOLE and FOCUS produce **22,982 rows each, with identical indices** - the comparison the original project ran but could not justify, since its WHOLE included crypto and therefore covered 24,232 rows against FOCUS's 22,441.
- **[RUNBOOK](docs/guides/RUNBOOK-getting-started.md)** - the first end-to-end guide, from a fresh clone to a feature matrix, explaining what every number on screen means. Its failure section carries the real stumbles rather than imagined ones: Smart App Control blocking mypy permanently and scipy transiently, a fresh clone having no `data/`, and what a `verify` mismatch actually means.
- **A quarantine guard in `tests/test_layering.py`**: `ta` may only be imported by `research/features/technical.py`. It ships no type information, so every symbol crossing that boundary arrives as `Any`, and `mypy --strict` is only worth having while the untyped surface stays small enough to audit.
- **`python -m forecast_lab.interfaces` as a second way in.** The `forecast-lab` console script is a generated `.exe` shim, and Windows Smart App Control refuses to launch a freshly built binary with no reputation - measured here, a shim installed days ago runs while one regenerated minutes earlier stays blocked across repeated attempts. Going through the interpreter sidesteps it, costs three lines, and removes a failure that looks like a broken install and is not.

### Fixed

- **ADX and ROC were missing from the feature set**, found by reading the original notebook instead of remembering it. The source computes 23 indicators per symbol; the first version of this slice built 15. Every one is now accounted for, and the mapping is recorded in [STATUS 2026-08-24](docs/status/STATUS-2026-08-features.md) sec. 2.
- **The scale gate was wrong twice, in different ways, and real data caught both within seconds.** Its threshold of `1e-9` flagged `bb_pband` - dimensionless by construction, but dividing by a Bollinger band's width, which amplifies floating-point error when the band is narrow. Then ADX moved by `7.1e-03`, four orders above the corrected threshold, and the clue was the shape rather than the size: **134 deviating rows out of 23,181, at consecutive positions**. ADX is a Wilder recursion over comparisons of consecutive highs and lows, so one tie broken the other way by rescaling propagates forward until it decays - while the 99th percentile stayed at `7.0e-10`. The verdict is now that percentile, with the maximum still printed beside it, because a large worst next to a tiny percentile is a real numerical instability rather than a price level.
- **The Wilder warm-up defect is not confined to ATR.** `ADXIndicator` also returns `0.0` across its entire warm-up with `fillna=False` - 27 zeros, no NaN anywhere. A zero is not "no data": it is *no trend at all*, a reading the market can produce, which `dropna()` will not remove and a tree will learn as a regime. The wrapper restores the NaN and the test asserts both halves, so a future `ta` release fixing it will say so.

## 2026-08-23 - The repository computes the number it has been quoting

### Added

- **[ADR-004](docs/adr/ADR-004-labels-splits-and-baselines.md), `research/labeling.py`, `research/splitting.py` and `research/baselines.py`** - the three decisions that stand between a panel and a result, each of which reads as one line of code and each of which the original analysis got wrong by not noticing it was making a decision. The horizon is a **timestamp** rather than a position, so `close.shift(-1)` cannot call Monday's close "the next hour"; an exact tie is **FLAT** rather than being swept into DOWN by a strictly-greater comparison; the split purges the label's reach at each boundary and carries **no embargo**, because a single chronological split has nothing after test and an embargo would delete real data to prevent a leak that cannot occur.
- **The majority-class baseline is fitted on train and applied blind**, and the distance to each block's own majority is printed beside it. That distance is the trap the original fell into, and it is not small: **2.01 points on validation and 1.06 on test**, both larger than the effect anyone is trying to detect. Accuracy never appears alone - precision, recall and specificity come with it, because 100% recall at **0.00% specificity** is what a constant looks like when only accuracy is reported, and that is exactly the pair the original's winning models show.
- **`forecast-lab baseline`**, with `--json`. It closes the repository's largest debt: the README asserted 51.53% and 51.86%, figures read out of a notebook that the code here could not compute. The corrected pipeline's equivalents are now produced from data by one command, recorded in **[STATUS 2026-08-23](docs/status/STATUS-2026-08-notebook-baseline.md)** with a machine-readable sidecar. On the test block, always-UP scores 51.46% and a **seeded coin flip scores 51.70%** - above it. Break-even is 51.92%; nothing available without a model reaches the floor.
- **What price does across the gaps, measured for the first time.** The 1,013 bars (4.37%) whose horizon spans a venue pause are marked rather than dropped, and the direction across them is now reported: gold rose **59.35%** of the time through the pause, against 50.87% across the stated horizon. The most visible directional skew in the dataset is not hourly direction - it is being long while the venue is shut. It stays unmodelled until a cost model can say whether it survives overnight financing, but measuring something and setting it aside is a different act from never looking.
- **[ADR-005](docs/adr/ADR-005-the-dashboard-runs-the-cli.md), at Plan status** - the dashboard will run `forecast-lab <command> --json` as a subprocess rather than importing `research` directly. Recorded now, built in Phase 4, because it constrains what every command from here on has to emit: importing `research` from a Streamlit script would create a second composition root, and the copy that drifts is the one nobody runs the gates against. It also means the page becomes a live demonstration of the reproducibility claim the README makes, with the command that produced each panel printed beneath it.

### Fixed

- **`seconds_ahead` came out a thousand times too small** - the same unit assumption that produced a wrong staleness figure during the alignment work, in a second place. Casting a `DatetimeIndex` to `int64` yields whatever resolution pandas chose, and dividing by a fixed `1e9` is only right when that resolution is nanoseconds; here it was microseconds. Both sites now subtract the timestamps and ask the result for seconds. Caught by a test written to check a gap distance, which is the argument for asserting on units rather than on shapes.

## 2026-08-22 - The target bars become the timeline

### Added

- **[ADR-003](docs/adr/ADR-003-target-anchored-alignment.md) and `research/align.py`** - the correction at the centre of the re-analysis. The target's own bars define the timeline and nothing else may extend it; auxiliary symbols are read onto it by carrying their last known value forward, which is legitimate because that value *was* the last thing known at that instant. The original pipeline outer-joined every symbol and forward-filled, inventing a row at every timestamp any symbol traded - and on the hours when the currencies were open and gold was not, gold's close became a copy of the previous bar. Measured on the real exports: 24,430 rows against 23,180, and 1,288 exact ties against 38. The forward fill **never creates an UP**, so all of it lands on one side and **flips which class is the majority** - the corrupted data says gold falls 51.47% of the time while the real series says it rises 51.15%. Every model was compared against a baseline that did not exist.
- **A regression test pinning the identity behind the damage**: each fabricated row adds exactly one tie. On the real data that reads 24,430 - 23,180 = 1,250 and 1,288 - 38 = 1,250. It runs on synthetic bars, because a test needing 19 MB of vendor data is a test that stops being run.
- **Per-symbol staleness.** Forward-filling is honest; losing track of how old the value is, is not - "the S&P is at 4,500" and "the S&P was at 4,500, sixteen hours ago" are different statements. One column per auxiliary, because the spread across symbols is too wide for a single number to describe: VIX is carried on 8.0% of rows and DXY on 7.1%, while the currencies stay under 0.2%. An optional `max_staleness` drops a value instead of letting Friday's close masquerade as a Monday price for 65 hours.
- **`forecast-lab align`**, which reports what had to be carried. On the reference panel: 23,181 rows, 59 columns, crypto absent from 25.5% of them because it starts a year late.

### Changed

- **Mixing timeframes is now refused, loudly.** A daily bar carried onto an hourly row has not closed when that hour's decision is taken, so its close describes hours that have not happened. This is the judgement ADR-002 sec. 6 deliberately left to alignment, the only step that knows the target and its interval.
- **Commit messages move to English.** The log is read by whoever opens the repository, and GitHub shows the newest message above the file list; a message that explains a decision is only worth writing in a language its reader has.

### Fixed

- **Staleness was computed a thousand times too small.** The integer view of a `DatetimeIndex` is in whatever resolution pandas chose - nanoseconds for the reference series, milliseconds for the fetched ones - so a fixed divisor was right for one and wrong for the other. Subtracting the timestamps and asking the result for seconds is resolution-independent. Caught by a test that asserted a two-hour gap and got seven seconds.
- **The layering guard would have flagged every `dict.get`.** Its list of I/O calls included `get`, which is ubiquitous; a guard that cries wolf on ordinary code trains everyone to ignore it. HTTP clients are caught by their import instead. Found the moment `research/` first existed and the guard stopped skipping.
- **mypy no longer runs on this platform** unless built from source: Windows Smart App Control blocks the mypyc-compiled extensions in its wheel, silently removing one of the three gates. `pyproject.toml` now pins a source build.

## 2026-08-19 - Ingestion, and a rule that real data refuted

### Added

- **The reading boundary** (`ingest/csv_reader.py`) - where a price series stops being bytes and starts being something the pipeline may trust. It parses UNIX epochs and ISO strings alike, normalises to timezone-aware UTC (a naive string is read as UTC, because reading it as local time would make the same file mean different things on two machines), sorts, and refuses what cannot be interpreted: a missing price column, an unparseable timestamp, a duplicated one. It never repairs. A repair this far upstream is a guess about what the venue meant, and the guess is invisible by the time it becomes a number in a report.
- **Provenance** (`ingest/manifest.py`, `forecast-lab verify`) - a committed manifest recording SHA-256, byte size, row count and time span per file, while the data itself stays out of the repository. The hash is the point: editing one digit of one price leaves the file exactly as long, changes every number computed from it, and announces nothing. It is a command rather than a test, because a test reading `data/` would skip itself in a clean clone and report green while guaranteeing nothing.
- **`forecast-lab ingest --from`** - validates an external directory and copies it in, reading every file *before* copying it so `data/` only ever holds series the rest of the pipeline may trust. Rejections are collected rather than raised on the first one: thirty files should not mean thirty round trips to learn about three problems.
- **`forecast-lab fetch`** - downloads bars from the public venue with no API key, which is what makes every published number reproducible by anyone who clones the repository. It fetches **both sides of the book** and writes mid prices plus **the spread of each bar**, because the spread is the transaction cost and the break-even accuracy that decides whether any edge is worth having is computed from it. Measured on real gold bars it is 0.75 USD mid-session and **9.5 at the weekly open** - an order of magnitude a constant assumption would have hidden. Requests are chunked by year (a single request for eight years is silently truncated), paced politely, and a failure is per symbol rather than per run.
- **Fifteen opt-in network tests** (`pytest -m network`) holding the venue to its side of the contract: that hourly bars still open exactly on the hour - the invariant the whole alignment design rests on - that both sides combine into a positive spread, that the spread is not constant, and that all twelve mapped instruments still exist. Excluded from the default gates, which stay hermetic.
- **`forecast-lab symbols` now shows row counts**, read from the manifest rather than by re-opening 34 files. The cheap question stays cheap.

### Changed

- **The grid rule of [ADR-002 sec. 6](docs/adr/ADR-002-data-source-and-symbol-set.md), rewritten because the data refuted it.** The ADR originally specified rejecting any series sitting on more than two grid offsets. Run against the real exports, that rule rejected six legitimate files. The cause was not corruption: **SPX and NDX daily and 4-hour bars sit at three offsets and DXY at four**, because a US instrument quoted on a European trading calendar crosses two daylight-saving regimes that do not switch on the same weekend, and **SPX daily carries 1,305 gaps shorter than 24 hours** - short sessions, not overlapping bars, since a "day" is a session rather than a duration. The threshold was measuring the calendar, not a defect. Grid shape is now recorded (`SeriesMeta.anchors`, `SeriesMeta.short_gaps`) and reported by `ingest`, and the judgement moves to alignment, which is the only step that knows the target and the horizon - and where the real hazard lives anyway, since a daily auxiliary bar is still open when an hourly decision is taken, however clean both grids are.

### Fixed

- **Manifest keys collided between data roots.** Entries were recorded relative to each command's destination, so a reference import and a fetch both produced the key `XAUUSD_1H.csv` and the second would have erased the first - in the one file whose whole job is to remove that ambiguity. Paths are now relative to `data/`. The same collision then reappeared in the row-count lookup, where `symbols --dir data/raw` reported the reference series' 24,401 bars for a directory holding 240; found by running the command, not by a test.
- **`pd.to_datetime` raises instead of yielding `NaT`** on an unparseable timestamp, so the reader's own check for missing values never ran. Caught by a test that asserted the project's error type and got pandas' instead.

## 2026-08-18 - The data source is measured before it is adopted, and the foundations are built

### Added

- **[STATUS 2026-08-18](docs/status/STATUS-2026-08-dukascopy-probe.md)** - a probe run before adopting any data source, answering five questions that were open: whether each of the twelve symbols exists, its coverage and density, how far back hourly history reaches, what anchor the bars use, and whether the venue quotes the same instrument as the reference exports. **Verdict: GO.** 457 of 457 hourly timestamps matched, with a return correlation of **0.9996** - the same instrument, not a lookalike. Two side findings changed the project: the comparison yielded a **measured spread of ~1.6 bps**, which replaces the assumed transaction cost in the break-even calculation, and the feed carries a **volume** column the reference exports lack, re-opening a family of indicators that had been out of reach.
- **[ADR-002](docs/adr/ADR-002-data-source-and-symbol-set.md)** - the data source and the symbol set, decided on the probe's evidence. Dukascopy because it is fetchable with no API key (so anyone who clones the repository can reproduce every number), extends forward (so a genuinely unseen holdout can exist at all), and can be hashed for provenance. The prior project's exports are kept in a separate directory and read exactly once, to reproduce its published baseline. Each `(symbol, timeframe)` is fetched independently rather than resampled, because a venue's higher-timeframe bars are anchored to its own trading day and that anchor moves with daylight saving time.
- **Contracts, the layering guard and the `symbols` command** - the first working slice. `Timeframe` knows its own duration; `SymbolSpec` refuses anything that would not survive as a file name on a case-insensitive filesystem; `SeriesMeta` rejects naive timestamps and carries grid anchors as a **set**, because a series whose trading day shifts with daylight saving legitimately has two. Series discovery reads file names only - the cheap question kept apart from the expensive one - via a configurable named-group regex rather than a positional split, so `BINANCE_BTC_USDT_1H.csv` cannot be misread as the symbol `USDT`. The scan is non-recursive on purpose and reports every file it ignored, because a scan that quietly skips half a directory is how somebody models a subset they did not choose.
- **[README](README.md)** and **[docs/INDEX.md](docs/INDEX.md)** - the front door and the one-line-per-file reference.

### Changed

- **VIX is dropped from the symbol set**, and the modelling window becomes 2018-01 onward. Its hourly history begins only in 2022-10, and it was the binding constraint on the whole set: keeping it costs **28,136 bars, 55% of the available sample**, to buy a feature whose measured correlation with the target is **-0.011**. The larger window lowers the minimum detectable effect - the smallest edge the design can tell apart from luck - from 52.12% to **51.42%** on a single split, which matters because the break-even accuracy sits at 51.92%. Realised volatility, computed causally from the target and the S&P, takes its place: it tracks the *level* of the fear regime at +0.75 against VIX, though not its *changes*, which is expected since one is forward-looking implied volatility and the other its backward-looking twin. The decision rests on an asymmetry rather than on proof - the cost is certain, the benefit is not - and the ADR says so.

### Fixed

- **The CLI collapsed into a bare command.** A Typer application holding a single command treats it as the root, so `forecast-lab symbols` failed with "unexpected extra argument". Fixed with an explicit callback, and the reason is recorded in the code so it does not get removed as redundant. The 52 tests all passed while this was broken - which is the argument for running the thing, not only testing it.
- **The command's help output was unreadable**, because Rich re-wraps a docstring and a long one came out shredded. Command docstrings are now a single line, with the reasoning in comments.

## 2026-08-17 - The architecture is decided, and what is deliberately not built is recorded

### Added

- **[ADR-001](docs/adr/ADR-001-hexagonal-architecture.md)** - four layers (`contracts`, `ingest`, `research`, `interfaces`) with dependencies pointing inward. The load-bearing rule is that **`research` may never reach for data**: it receives frames and cannot open a file or call an API, because a layer that can quietly re-read the world produces experiments that cannot be reproduced from stored inputs, and a result that cannot be reproduced cannot be falsified. The ADR also records what is deliberately *not* built - no ports package, no storage layer - on the grounds that an abstract interface earns its place when a second implementation exists, and today there is exactly one source feeding one caller. It closes two holes in the dependency guard along the way: relative imports of the form `from .. import x` are invisible to the obvious implementation, and a module sitting at the package root is neither attributed to a layer nor checkable against one, which is precisely where a leak would hide.
